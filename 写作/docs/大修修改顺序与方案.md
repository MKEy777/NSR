# NSR 大修修改路线图：按实际修改落点合并审稿意见

> 适用稿件：`NSR_Author/main.tex`、`NSR_Author/supplement.tex`  
> 审稿意见来源：`docs/大修意见.md`  
> 编排依据：`docs/Manuscript_Instructions.md` 与 `docs/SNN.pdf`  
> 本文档目标：不是按宽泛“问题主题”分组，而是把**需要修改同一段正文、同一组公式、同一张图表或同一补充小节**的意见放在一起，形成可直接执行的修改顺序。

## 0. 使用原则

### 0.1 分组规则

1. **以实际修改落点为主键**：同一意见即使来自不同审稿人，只要最终修改同一段、同一公式组、同一图或同一表，就放入同一组。
2. **一条复合意见可以拆开处理**：例如 R1-5 同时涉及术语和指标定义，分别落到“全稿术语”与“性能结果/表格”两组；R2-5 同时涉及 GALS 接口和 40 mW 测量边界，分别落到硬件图示组与效率比较组。
3. **每组均分为三类交付物**：
   - **正文**：读者理解核心贡献和结论所必需的信息；
   - **补充材料**：完整协议、推导、实现细节、扩展实验和统计；
   - **回复信**：解释修改逻辑、证据与范围，避免把所有问题都表述成“原稿存在严重缺陷”。
4. **实验未完成时只写结构与占位，不虚构结果**：所有均值、标准差、SNR、资源开销和 Jacobian 指标均须在结果冻结后回填。

### 0.2 执行标签

- **[W] 写作即可完成**：不依赖新增实验，核对原文或代码事实后即可落笔。
- **[W/V] 写作 + 事实核验**：不一定需要重跑实验，但必须核对代码、日志、综合报告或数据处理流程。
- **[E] 新实验/新分析后回填**：先搭好文字、表格和回复信结构，结果冻结后完成。

### 0.3 回复信的总基调：扬长避短，但不回避事实

回复信不采用反复“we agree that this is a major limitation”的写法，而采用以下顺序：

1. **准确承接关切**：指出审稿人关心的是可复现性、公平性、边界或可解释性中的哪一项。
2. **说明原稿已有基础**：如果内容已经存在但不够显眼，应写成“the original manuscript did not make this distinction sufficiently explicit”，而不是承认方法本身不存在。
3. **报告具体修改**：明确正文、补充材料、图表或公式改了什么。
4. **突出已有或新增证据**：先讲支持本文贡献的证据，再讲范围限定。
5. **必要时收窄主张**：将无法完全支持的部署、鲁棒性或理论保证改为受证据约束的表述，但不把整项贡献降格为缺陷。
6. **未来工作只作为扩展**：在线适应、ASIC 和真实穿戴场景应表述为对当前离线推理系统的自然扩展，而不是当前工作无效的原因。

# 1. NSR 正文—补充材料边界

## 1.1 必须遵守的 NSR 约束

- Research Article 正文不超过 **5000 words**；当前正文粗略统计约 **3399 words**，有修改空间，但不适合把所有审稿细节搬入正文。
- 正文图和表合计最多 **6 项**；当前 `main.tex` 已经正好有 **6 项**，因此原则上：
  - 不新增独立正文图表；
  - 新实验优先进入 Supplementary Figures/Tables；
  - 如确有必须进入正文的证据，只能合并、替换或重构现有图表。
- `METHODS` 位于 `CONCLUSION` 之后且不超过 **500 words**。当前 Methods 是简短的补充材料指引，和 `docs/SNN.pdf` 的 NSR Research Article 处理方式一致，不应按普通期刊思路扩写成长篇 Methods。
- 摘要为单段、最多 **150 words**，应突出意义、核心推进和最强证据，不应塞入协议细节。
- 补充材料用于详细方法、完整推导、扩展数据分析、附加图表和实现细节；正文必须保留理解中心结论所需的最小充分信息。
- 所有正文图需按 NSR 要求补充 `Alt text:`；图中文字、符号说明和最终字号也需统一检查。`nsr_sample.bib` 当前含 57 条目，最终还需核对正文实际引用数；若超过 50，必须合并或删减非关键引用。

## 1.2 参考 `docs/SNN.pdf` 的内容分配方式

该 NSR 论文采用的结构可概括为：

- **正文 Results**：保留核心机制、关键方程、决定性结果和主叙事；
- **Supplementary Notes**：放完整推导、假设、边界条件和补充解释；
- **Supplementary Experiments**：放扩展学习曲线、额外消融和更细结果；
- **正文 Methods**：保持极简，并指向 Supplementary data。

因此，本稿大修不应把每个审稿问题都扩写进正文。正确策略是：正文补足“读者必须知道什么”，补充材料解决“专家如何验证和复现”，回复信解决“为什么这样修改足以回应关切”。

### 已确认的协议口径

#### A. 主结果与跨被试结果的准确命名

| 结果层级 | 数据集 | 准确协议名称 | 划分与测试对象 | 结果位置 |
|---|---|---|---|---|
| Main benchmark | 五个数据集 | Subject-dependent random window-level 80/20 evaluation | 从全部 outer windows 中随机划分约 80% train、20% held-out evaluation；subjects 和 trials 可同时出现在两侧 | Main Table 1 |
| Subject-independent generalization | SEED / SEED-IV / SEED-V | Leave-one-subject-out（LOSO） | 每个 split 留出一个完整 subject；该 subject 的所有 sessions、trials 和 windows 均不进入训练 | Supplementary Table |
| Subject-independent generalization | DEAP | Five fixed cross-subject subject-holdout splits（approximately 80/20） | 32 subjects；每个 split 为 26 train subjects + 6 held-out subjects | Supplementary Table |
| Subject-independent generalization | DREAMER | Five fixed cross-subject subject-holdout splits（approximately 80/20） | 23 subjects；每个 split 为 19 train subjects + 4 held-out subjects | Supplementary Table |

执行时必须遵守以下命名边界：

- 将结果文件中 DEAP/DREAMER 的旧标题 `Subject-Dependent 80/20` 改写为 **five fixed cross-subject subject-holdout splits**。
- 不写 `five-fold cross-validation`：五个 split 是预定义的固定 subject holdouts，并不构成每名受试者恰好一次进入测试集的标准互斥五折覆盖。
- `approximately 80/20` 只描述 subject 数量比例，不得让读者误以为是每名被试内部的 trial/window 80/20。
- 正文可简称 `subject-dependent benchmark`，但 Supplementary Methods 和 Table 1 表注必须进一步写明其为 **random window-level 80/20**，而不是 subject-level 或 trial-level split。

#### B. 窗口长度、stride 与 PSE temporal bins

| 数据集 | Outer window | Stride | Outer-window overlap | 每个 outer window 内的 PSE temporal bins |
|---|---:|---:|---|---|
| SEED | 4 s | 4 s | 无重叠 | 4 个连续 1-s bins |
| SEED-IV | 4 s | 4 s | 无重叠 | 4 个连续 1-s bins |
| SEED-V | 4 s | 4 s | 无重叠 | 4 个连续 1-s bins |
| DEAP | 9 s | 9 s | 无重叠 | 6 个连续 1.5-s bins |
| DREAMER | 9 s | 9 s | 无重叠 | 9 个连续 1-s bins |

必须修正现有补充表的概念错误：其中的 1 s 或 1.5 s 是 **PSE temporal-bin length**，不是 sliding-window duration 或 stride。所有五个数据集的 outer windows 均为 non-overlapping。

#### C. subject/session/trial 元数据

- 每个 outer window 均携带 `subject_id`、`session_id` 和 `trial_id`。
- SEED、SEED-IV、SEED-V：`session_id` 为 1–3；`trial_id` 是该 session 内的 trial 序号。
- DEAP、DREAMER：按单 session 处理，使用占位 `session_id = 0`；`trial_id` 是该 subject 内的 trial 序号。
- 唯一 trial key 写为 `(subject_id, session_id, trial_id)`，避免不同 subjects 或 sessions 中相同 trial 序号被错误合并。

#### D. LDS 的计算范围与顺序

- 先对每个 outer window 计算 PSE 并进行空间映射，形成 trial 内按时间排序的序列，形状为 `M × N_f × H × W`；其中 `M` 为该 trial 的 outer-window 数。
- 对每个 trial 单独进行 LDS：在每一个固定的 `(frequency, H, W)` 位置上，沿长度为 `M` 的 outer-window 序列平滑。
- LDS 不跨越 trial、session 或 subject 边界；只有一个 outer window 的 trial 保持不变。
- 该描述只证明 LDS 的**作用域是 trial 内**，不能自动推出 train/test 独立。对于正文 random window-level 80/20，同一 trial 的不同 windows 可分别进入 train 与 held-out evaluation，而且这些 windows 在拆分前已参与同一 trial 内的 LDS 平滑。因此不得写“trial-level mutual exclusion”“LDS eliminates leakage”或“fully leakage-free subject-dependent evaluation”。

#### E. 指标与统计口径

- **Accuracy**：所有 held-out samples/windows 上预测正确的比例。
- **Macro-F1**：各类别 F1 的非加权平均。
- **Macro-specificity**：先对每一类进行 one-vs-rest 计算 `TN/(TN+FP)`，再对类别取非加权平均。
- 多次运行或多个 split 的汇总采用 arithmetic mean；sample standard deviation 使用 `ddof = 1`。
- Main Table 1 中 DA-SNN 的 `mean ± std` 按生成该结果的重复 seeds/runs 报告；执行时从最终运行记录复制准确 seed 列表，不从旧稿猜测。
- SEED-family cross-subject 文件已有 `mean ± std`，保持其报告形式。DEAP/DREAMER 当前源文件只有 point estimates，不补造 `± std`；如无法恢复 split-level 数据，表注明确其为 five-split aggregate point estimate。

#### F. validation、checkpoint selection 与最终评价

本项按作者确认从“部分协议”更正为“所有 EEG 协议”：

- 所有已报告 EEG protocols 均未设置独立 validation subset；实现中每个 split 都采用 `val_indices = test_indices`。
- 训练过程逐 epoch 计算该 held-out evaluation partition 的 accuracy，并据此执行 checkpoint selection/early stopping；最终指标由所选 checkpoint 在同一 partition 上计算。
- 因此正文和补充材料不得使用 `independent validation set`、`untouched test set` 或“模型选择完全不访问 test data”等不实表述。
- 可陈述的公平性边界是：统一重评的 neural models 使用相同的预定义 splits 和相同 checkpoint-selection rule；在 cross-subject protocols 中，held-out subjects 仍与训练 subjects 互斥。
- 这一统一性支持**同协议模型比较**，但不能消除使用同一 partition 进行 checkpoint selection 与最终报告所带来的潜在选择偏差。回复信须透明说明事实，同时通过收窄结论边界避免把该问题扩大成对模型机制或硬件贡献的全面否定。

### 本组的关键风险门与当前写作决策

1. **正文 SD 结果不是 trial-independent 或 subject-independent 评价。** random window-level 80/20 允许同一 subject、同一 trial 的 windows 同时出现在 train 与 held-out evaluation。
2. **LDS 在 split 前按完整 trial 计算。** 因此正文 SD 结果只能作为 subject-dependent benchmark comparison，不能用于证明 unseen-subject、unseen-trial 或严格 leakage-free generalization。
3. **当前采用 writing-only 可落地方案：**准确重命名协议、公开 split unit 与模型选择口径、收窄主张，并用补充 cross-subject 结果回应泛化问题；不通过文字声称已经消除了不存在的独立性风险。
4. 如果后续希望写出“strict trial-level independence”或“independent test evaluation”，必须新增实验：按 composite trial key 拆分后再进行不跨 split 的预处理，并从训练集内部建立 validation set。该实验不属于本轮已经确认的写作修改，不能在回复信中提前宣称完成。

1. **Reviewer comment**：完整保留原意见和编号。
2. **Response opening**：一至两句准确概括关切，不泛泛感谢。
3. **What was clarified/changed**：先说明原有基础，再说明具体修订。
4. **Evidence**：给出新增实验、分析、公式或图表；没有新增证据时不伪装成已完成。
5. **Manuscript location**：正文页码/行号、Supplementary section、figure/table/equation。
6. **Revised text**：引用短而关键的修订文本，不整段复制论文。
7. **Scope statement**：仅在必要时说明边界，并以当前贡献和未来扩展收束。

### 不同意见采用的主要回应姿态

| 类型 | 适用意见 | 回应方式 |
|---|---|---|
| 表述不清但机制已存在 | R1-4, R1-6, R3-4, R4-3/4/7 | `CLARIFY_EXISTING`：强调重绘、集中定义和交叉引用 |
| 明确文字/格式错误 | R1-5, R2-6, R3-2, R4-2/5/6/8/9/13/17/19 | `ACCEPT_TEXT`：直接修正，不展开辩论 |
| 需要新增实验或分析 | R1-3, R3-1/3, R4-16/23 | `ACCEPT_ANALYSIS`：报告协议和新证据，不预写结果 |
| 主张过宽 | R2-1/3/5, R4-15/22 | `PARTIAL` 或 `SOFTEN_CLAIM`：保留可靠贡献，收窄不受支持的外延 |

| 创新归属需澄清 | R4-10/11/21 | `CLARIFY_EXISTING + REFRAME_STRENGTH`：明确 inherited/modified/new |

### 最终核查

1. 每条回复必须出现至少一个明确修改位置；若无修改，必须给出有证据的理由。
2. 不能写“we added experiments”而结果尚未完成。
3. 不能在回复信收窄 claim，却在摘要、Conclusion 或图注继续保留原强表述。
4. 正文引用的每个 Supplementary Note/Figure/Table 必须真实存在且编号正确。
5. 最终再检查 NSR 限制：正文词数、摘要词数、6 项图表、Methods ≤500 words、≤50 references、alt text、表格格式。

## 最终执行原则

这轮大修的核心不是“把所有内容都塞进正文”，也不是“对每条意见都承认一个局限性”，而是：

1. 用正文补足中心逻辑和决定性证据；
2. 用补充材料提供专家可核查的完整协议、推导、实现和扩展实验；
3. 用回复信说明原稿基础、具体修改和证据边界；
4. 对确实过宽的主张主动收窄，但把本文已证明的跨层协同、稀疏事件生成和 FPGA 实证放在回应中心；
5. 在 NSR 的 5000-word 与 6-display-item 约束下，通过重写、合并和交叉引用提升可信度，而不是简单扩篇。
